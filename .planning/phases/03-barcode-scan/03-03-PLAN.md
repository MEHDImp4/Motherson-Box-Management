# Phase 3 — Wave 3: Simulator Upgrade & Tests

## Goal

Upgrade the simulator panel to use the AJAX `ScanAjax` endpoint with CSRF tokens, show per-scan result badges inline, and update the UI incrementally (no page reload). Add integration tests covering scan-on-completed-box, scan-on-nonexistent-box, AJAX JSON endpoint, and audit-log creation.

<task id="03-03-01">
<objective>Upgrade _SimulatorPanel.cshtml to use AJAX endpoint with CSRF, per-scan results, and incremental UI (D-07, D-08, D-09, D-10)</objective>

<action>
1. Change the `@model` directive from `MothersonBoxManagement.Data.Dtos.BoxDetailsDto` to `MothersonBoxManagement.ViewModels.PrepareViewModel`.
2. Update all `Model.Id` references to `Model.Box.Id` and `Model.BarcodeValue` to `Model.Box.BarcodeValue`.
3. Replace the `<form asp-action="Scan" ...>` with a non-submitting form (no `asp-action`, add `onsubmit="return false;"`). Keep the hidden inputs for boxId and boxBarcode but use `Model.Box.Id` and `Model.Box.BarcodeValue` (D-10).
4. Add a results container div `<div id="simResults" class="mt-2"></div>` below the form for per-scan badge display.
5. Rewrite the `doSimScan()` JavaScript function:
   - Read CSRF token from `document.querySelector('meta[name="RequestVerificationToken"]').content`.
   - For each scan iteration, build `FormData` with boxId, boxBarcode, and generated barcode.
   - Call `fetch('/Box/ScanAjax', { method: 'POST', headers: { 'X-CSRF-TOKEN': csrfToken }, body: formData })`.
   - Parse JSON response.
   - For each scan result, append a badge to `#simResults`: `<span class="scan-result-badge ${data.success ? 'success' : 'error'}">${barcode}: ${data.message}</span>`.
   - If `data.success`, call `addPackageRow(data.package)` and `updateProgressBar(data.currentQuantity, data.expectedQuantity)` from scanner.js (shared functions).
   - If `data.status === "Completed"`, call `disableScanInput()` and break the loop.
   - Update button text with progress `Scan X/N...` (D-07).
6. Remove the `window.location.reload()` call at the end. The UI is now updated incrementally.
7. Re-enable the button after all scans complete and set text back to `"Générer et scanner"`.
8. Toggle button for simulator panel toggles using a simple JS toggle handler (D-09).
9. Barcodes generated in simulator use format `PKG-TEST-{timestamp}` (D-08).
</action>

3. Add test `ScanAjax_ReturnsJsonOnSuccess`:
   - Login as OP001, create a box.
   - POST to `/Box/ScanAjax` with valid formData (boxId, boxBarcode, barcode=PKG-AJAX-001).
   - Note: Since tests use `CustomWebApplicationFactory` without anti-forgery configured (InMemory), the test must handle CSRF. The factory doesn't add anti-forgery, so this may need the test factory to be updated with `services.AddAntiforgery(options => options.SuppressXFrameOptionsHeader = true);` or the test client to send the CSRF header. Alternative approach: add the test but if CSRF blocks it in InMemory, add `[IgnoreAntiForgeryToken]` on ScanAjax for test or configure the factory to disable antiforgery validation via `services.Configure<AntiforgeryOptions>(o => o.Cookie.Name = "af"); services.AddAntiforgery();`. Simplest: add to CustomWebApplicationFactory `builder.ConfigureServices(services => { services.AddAntiforgery(o => o.SuppressXFrameOptionsHeader = true); })` and send X-CSRF-TOKEN header from test.
   - Actually, the simplest approach for integration tests with `WebApplicationFactory`: the test client can GET the page first, extract the token from the meta tag, then send it in the POST header. Implement this helper method `GetCsrfTokenAsync(HttpClient client, string pageUrl)` that GETs the page, parses `<meta name="RequestVerificationToken" content="...">`, and returns the token value plus the cookie.
   - Assert: response status 200, content-type `application/json`, body contains `"success":true`, `"message"` contains `"Scan réussi"`.

   - Assert: at least one `BoxAuditLog` entry exists with `ActionType == "PackageScan"` and `DetailsJson` containing the scanned barcode.
 
5. Add test `ScanOnCapacityReachedBox_Rejected` (D-13):

   - Scan a 3rd package.
   - Assert: redirect response, page contains "n'est pas ouverte" or "quantité attendue est déjà atteinte".
 
6. Add test simulating concurrent scans to verify unique constraints (D-12).
