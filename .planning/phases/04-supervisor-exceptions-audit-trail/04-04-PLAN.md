At line 59 of BoxController.cs, the role check for populating ViewBag.OpenBoxes only tests "Superviseur" and "Admin".     if (User.IsInRole("Superviseur") || User.IsInRole("Admin") || User.IsInRole("Supervisor") || User.IsInRole("Administrator"))

        var openBoxes = await _boxService.GetOpenBoxesAsync(cancellationToken);
        ViewBag.OpenBoxes = openBoxes.Where(b => b.Id != box.Id).ToList();
    }

This ensures the transfer modal dropdown populates regardless of which role name variant is used in the cookie claim.

**Part A — AuditSaveChangesInterceptor.cs (lines 102-138):**

Replace the current verbose dump that serializes ALL OriginalValues and ALL CurrentValues with a ChangedProperties-focused approach:

1. Add `using System.Text.Json.Serialization;` at the top.

2. Replace the details anonymous object (lines 121-127) with a structure that includes a ChangedProperties dictionary containing only properties whose values differ. For Added entities, ChangedProperties contains the new values. For Deleted entities, ChangedProperties contains the old values. For Modified entities, ChangedProperties maps property name to an object with Old and New values.

3. Create a JsonSerializerOptions with `JsonStringEnumConverter` so enums like BoxStatus serialize as "Open", "Cancelled", etc. instead of integers. Use this options object in the `JsonSerializer.Serialize(details, options)` call.

4. Keep the OriginalValues and CurrentValues dictionaries in the output for backward compatibility, but make ChangedProperties the primary field.

5. Serialize only the ChangedProperties in the top-level JSON to keep output compact. Remove the verbose full OriginalValues/CurrentValues dumps from the serialized JSON (they can remain as local variables for the ChangedProperties computation).
