# Phase 4 - Plan 1: Database Updates & Audit Interceptor

<objective>
Update the `BoxPackage` entity with blocking properties and implement the EF Core `SaveChangesInterceptor` to automatically generate `BoxAuditLog` entries for all database modifications.
</objective>

<tasks>

## Task 1: Update BoxPackage Entity & Migrations
<read_first>
- `MothersonBoxManagement/Entities/BoxPackage.cs`
- `MothersonBoxManagement/Data/ApplicationDbContext.cs`
</read_first>
<action>
1. Add `public bool IsBlocked { get; set; } = false;` to `BoxPackage`.
2. Add `public string? BlockReason { get; set; }` to `BoxPackage`.
3. Generate a new EF Core migration named `AddBoxPackageBlocking`.
4. Apply the migration to the database.
</action>
<acceptance_criteria>
- `BoxPackage` contains `IsBlocked` and `BlockReason` properties.
- Migration is successfully generated and applied without data loss.
</acceptance_criteria>

## Task 2: Workstation Configuration
<read_first>
- `MothersonBoxManagement/appsettings.json`
- `MothersonBoxManagement/appsettings.Development.json`
</read_first>
<action>
1. Add a `"WorkstationName": "DEV-STATION-01"` setting to `appsettings.Development.json`.
2. Add `"WorkstationName": "DEFAULT-STATION"` to `appsettings.json`.
</action>
<acceptance_criteria>
- Both configuration files contain the `WorkstationName` key at the root level.
</acceptance_criteria>

## Task 3: Implement Audit Interceptor
<read_first>
- `MothersonBoxManagement/Entities/BoxAuditLog.cs`
- `MothersonBoxManagement/Data/ApplicationDbContext.cs`
- `MothersonBoxManagement/Program.cs`
</read_first>
<action>
1. Create `MothersonBoxManagement/Data/Interceptors/AuditSaveChangesInterceptor.cs` implementing `SaveChangesInterceptor`.
2. Inject `IHttpContextAccessor` (to get current user ID) and `IConfiguration` (to get `WorkstationName`).
3. Override `SavingChangesAsync`. For each changed entity (Added, Modified, Deleted) *except* `BoxAuditLog` itself:
   - Identify the `BoxId` if applicable (e.g., if entity is `Box` or `BoxPackage`).
   - Serialize the `OriginalValues` and `CurrentValues` to JSON to form the `DetailsJson`.
   - Map `EntityState` to the appropriate `ActionType` string.
   - Create a `BoxAuditLog` instance and add it to the DbContext.
4. Register the interceptor in `Program.cs` as a scoped service and add it to the `DbContextOptionsBuilder` via `AddInterceptors`.
5. Remove any existing manual `BoxAuditLog` insertions (e.g. from `BoxService.ScanPackageAsync`) since the interceptor will now handle this.
</action>
<acceptance_criteria>
- `AuditSaveChangesInterceptor` successfully captures entity changes and adds `BoxAuditLog` records before save.
- `BoxAuditLog` is excluded from being audited to prevent infinite loops.
- `WorkstationName` is correctly read from config.
</acceptance_criteria>

</tasks>

<verification>
1. Run the application and scan a package into a box.
2. Check the `BoxAuditLog` table in the database to verify a record was created automatically with the correct `DetailsJson`, User ID, and Workstation Name.
3. Verify `BoxPackage` table has the new blocking columns.
</verification>

## Must Haves
- The interceptor MUST handle cases where `IHttpContextAccessor.HttpContext` is null (e.g., background tasks).
- The interceptor MUST gracefully find the `BoxId` if the modified entity is a `BoxPackage`.

## Artifacts this phase produces
- EF Core Migration for BoxPackage.
- `AuditSaveChangesInterceptor.cs`
