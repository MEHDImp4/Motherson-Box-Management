# Phase 4 - Plan 2: Supervisor Exception Service Layer

<objective>
Implement the core business logic for all supervisor exception actions (Cancel, Force Close, Update Expected Quantity, Block/Unblock Box, Block/Unblock Package, Transfer Package, Remove Package) in the `BoxService`.
</objective>

<tasks>

## Task 1: Add ExceptionReason to Box Entity
<read_first>
- `MothersonBoxManagement/Entities/Box.cs`
- `MothersonBoxManagement/Data/ApplicationDbContext.cs`
</read_first>
<action>
1. Add `public string? ExceptionReason { get; set; }` to the `Box` entity.
2. Generate an EF Core migration named `AddBoxExceptionReason` and apply it.
</action>
<acceptance_criteria>
- `Box` entity contains `ExceptionReason`.
- Migration is successfully applied.
</acceptance_criteria>

## Task 2: Box Exception Methods
<read_first>
- `MothersonBoxManagement/Services/IBoxService.cs`
- `MothersonBoxManagement/Services/BoxService.cs`
</read_first>
<action>
1. Add the following methods to `IBoxService` and implement them in `BoxService`:
   - `Task<BoxDetailsDto> CancelBoxAsync(int boxId, string reason, int userId, CancellationToken ct = default);` (Sets status to Cancelled)
   - `Task<BoxDetailsDto> ForceCloseBoxAsync(int boxId, string reason, int userId, CancellationToken ct = default);` (Sets status to CompletedWithException)
   - `Task<BoxDetailsDto> UpdateExpectedQuantityAsync(int boxId, int newQuantity, string reason, int userId, CancellationToken ct = default);` (Updates ExpectedQuantity)
   - `Task<BoxDetailsDto> BlockBoxAsync(int boxId, string reason, int userId, CancellationToken ct = default);` (Sets status to Blocked)
   - `Task<BoxDetailsDto> UnblockBoxAsync(int boxId, string reason, int userId, CancellationToken ct = default);` (Reverts status to Open)
2. In each method:
   - Load the `Box` with pessimistic concurrency/retry loop if necessary.
   - Validate state (e.g., cannot force close a cancelled box).
   - Update the `Status` or `ExpectedQuantity`, and set `ExceptionReason = reason`.
   - Set `LastModifiedByUserId = userId`.
   - Call `SaveChangesAsync()`.
</action>
<acceptance_criteria>
- All 5 methods exist in `IBoxService` and are fully implemented in `BoxService`.
- State validation ensures logical progression (e.g., only open boxes can be cancelled/force closed).
</acceptance_criteria>

## Task 3: Package Exception Methods
<read_first>
- `MothersonBoxManagement/Services/IBoxService.cs`
- `MothersonBoxManagement/Services/BoxService.cs`
</read_first>
<action>
1. Add the following methods to `IBoxService` and implement them in `BoxService`:
   - `Task<BoxDetailsDto> BlockPackageAsync(int packageId, string reason, int userId, CancellationToken ct = default);`
   - `Task<BoxDetailsDto> UnblockPackageAsync(int packageId, string reason, int userId, CancellationToken ct = default);`
   - `Task<BoxDetailsDto> TransferPackageAsync(int packageId, int destinationBoxId, string reason, int userId, CancellationToken ct = default);`
   - `Task<BoxDetailsDto> RetraitPackageAsync(int packageId, string reason, int userId, CancellationToken ct = default);`
2. Logic for Block/Unblock:
   - Set `IsBlocked = true/false` and `BlockReason = reason`.
3. Logic for Transfer:
   - Load source box, destination box, and package.
   - Validate both boxes are open, and destination is not full.
   - Update `BoxId` on the package.
   - Decrement `CurrentQuantity` on source box.
   - Increment `CurrentQuantity` on destination box.
   - Save changes in a single transaction.
4. Logic for package removal:
   - Load box and package.
   - Remove the `BoxPackage` from the DbContext entirely.
   - Decrement `CurrentQuantity` on the box.
   - Save changes.
</action>
<acceptance_criteria>
- All 4 methods are implemented correctly.
- Transfer atomic properties are maintained using EF transactions.
- Package removal correctly removes the package and updates quantities.
</acceptance_criteria>

</tasks>

- Proper EF Core transactions MUST be used for multi-entity updates like Transfer.
- Proper CancellationToken propagation.
